# 모의 2-3 복사기 - 해설

[정답 코드](solution.cpp) · [문제](../../problems/e2c-copiers/problem.md)

**사용한 방법: 답에 대한 이분탐색(매개변수 탐색)** - 관련 단원 [07](../../units/07-binary-search/README.md)

## 접근

"T초 안에 K장을 만들 수 있는가?"는 쉽게 판정할 수 있다: 복사기 i는 T초 동안 `T / t_i`장을 만들므로
`sum(T / t_i) >= K`인지 보면 된다(O(N)).

T가 커질수록 만들 수 있는 장수는 줄지 않는다 → 판정 결과가 `불가능 … 불가능 가능 가능 …`으로 **단조**.
첫 번째 "가능"을 이분탐색으로 찾는다.

- 하한 1, 상한 `min(t) × K`(가장 빠른 복사기 혼자서도 끝나는 시간).
- `가능 → hi = mid`, `불가능 → lo = mid + 1`. 최솟값을 찾는 형태이므로 `mid`는 내림.

07b(리본 자르기)는 "가능한 최댓값", 이 문제는 "가능한 최솟값"을 찾는다는 점이 다르다.
두 형태의 갱신 방향과 `mid` 계산(올림/내림)을 구분해 두자.

## 자료형

- 답의 최댓값: 10^9 × 10^9 = 10^18 → `long long`(최대 약 9.2×10^18)에 들어간다.
- 판정 중 장수의 합: `mid ≤ min(t) × K`이므로 각 항은 K 이하, 합은 N×K ≤ 10^14.
  상한을 무작정 크게(예: 4×10^18) 잡으면 합이 오버플로할 수 있다. 정답 코드처럼 K에 도달하면 바로 반환하면 더 안전하다.

## 복잡도

- 시간: O(N log(min(t)×K)) ≈ 10^5 × 60. 공간: O(N).

## 자주 하는 실수

- 1초씩 늘려 가며 시뮬레이션 → 답이 10^18까지 가능하므로 불가능.
- 답이나 상한을 `int`로 선언.
- `(lo + hi) / 2`에서 `lo + hi`가 오버플로(상한이 10^18일 때 2×10^18은 괜찮지만, 습관적으로 `lo + (hi - lo) / 2`를 쓴다).
- 최솟값 탐색인데 `lo = mid`로 갱신해 무한 루프.
