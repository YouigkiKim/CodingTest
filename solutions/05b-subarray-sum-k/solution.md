# 05b 합이 K인 구간 - 해설

[정답 코드](solution.cpp) · [문제](../../problems/05b-subarray-sum-k/problem.md)

## 접근

구간 `(i, j]`의 합은 `prefix[j] - prefix[i]`이다. 이것이 K가 되려면

```
prefix[i] == prefix[j] - K     (단, i < j)
```

따라서 j를 왼쪽에서 오른쪽으로 옮기면서 "앞에서 누적합이 `prefix[j] - K`였던 위치가 몇 개인가"를
해시맵으로 세면 된다. 04b(합이 T인 쌍)와 같은 구조에 누적합을 얹은 것이다.

`seen[0] = 1`로 시작하는 이유: 맨 앞에서 시작하는 구간은 "아무것도 더하지 않은 누적합 0"과 짝을 이루기 때문이다.

### 작은 예 (a = 1 2 1 2 1, K = 3)

| j | prefix | 찾는 값 prefix-K | 찾은 개수 | seen (등록 후) |
|---|---|---|---|---|
| - | 0 | - | - | {0:1} |
| 1 | 1 | -2 | 0 | {0:1, 1:1} |
| 2 | 3 | 0 | 1 | {0:1, 1:1, 3:1} |
| 3 | 4 | 1 | 1 | {…, 4:1} |
| 4 | 6 | 3 | 1 | {…, 6:1} |
| 5 | 7 | 4 | 1 | {…, 7:1} |

합계 4.

## 왜 투 포인터가 아닌가

원소에 음수가 있으면 구간을 늘린다고 합이 커지지 않으므로, 08단원의 투 포인터 논리가 성립하지 않는다.
누적합 + 해시는 부호와 무관하게 동작한다.

## 복잡도

- 시간: 평균 O(N). 공간: O(N).
- 답은 최대 N(N+1)/2 ≈ 2×10^10 → `long long`.

## 자주 하는 실수

- `seen[0] = 1` 누락 → 맨 앞에서 시작하는 구간을 놓친다.
- 현재 누적합을 **먼저 등록**하고 세어서 K=0일 때 길이 0인 구간을 센다.
- 누적합·K·답을 `int`로 선언.
