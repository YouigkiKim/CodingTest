# 11b 격자 최대 합 - 해설

[정답 코드](solution.cpp) · [문제](../../problems/11b-grid-path/problem.md)

## 접근

| 요소 | 내용 |
|---|---|
| 상태 | `best[i][j]` = 시작 칸에서 (i, j)까지 오는 경로의 최대 합 |
| 점화식 | `best[i][j] = max(best[i-1][j], best[i][j-1]) + v[i][j]` |
| 초기값 | `best[0][0] = v[0][0]`, 첫 행은 왼쪽에서만, 첫 열은 위에서만 |
| 계산 순서 | 행 우선(위→아래, 왼쪽→오른쪽). 필요한 위/왼쪽 칸이 항상 먼저 계산된다 |

(i, j)에 오기 직전 칸은 위 또는 왼쪽뿐이다. 둘 중 더 좋은 쪽에서 오는 것이 최선이다.

## 왜 그리디가 아닌가

"지금 갈 수 있는 두 칸 중 큰 쪽으로 간다"는 예제 2에서 실패한다.

```
1 2 1
1 1 1
100 1 1
```

시작에서 오른쪽(2)이 아래(1)보다 크지만, 아래로 가야 100을 지날 수 있다. 그리디는 6, 정답은 104.

## 복잡도

- 시간: O(H×W). 공간: O(H×W).
- 경로는 H+W-1 ≤ 599칸, 값은 ±10^9 → 합은 ±6×10^11 → `long long`.

## 자주 하는 실수

- 경계 밖을 0으로 취급(`best`를 0으로 채우고 `max(위, 왼쪽)`을 그대로 적용) → 값이 음수일 때
  실제로는 올 수 없는 "격자 밖 0"이 선택되어 틀린다. 예: 1×4 격자 `1 -2 3 -4`.
- 합을 `int`로 계산.
- 모든 경로를 재귀로 탐색 → 경로 수가 지수적으로 많아 시간초과.
