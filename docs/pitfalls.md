# 자주 하는 실수 모음

[전체 목차](../README.md) · [STL 치트시트](cheatsheet.md) · [복잡도 가이드](complexity.md)

오답·런타임 오류의 대부분은 아래 목록에서 나온다. 문제를 틀렸을 때 이 목록부터 대조해 본다.
각 항목은 **잘못된 코드 → 왜 틀리는가 → 고친 코드** 순서다.

## 1. int 오버플로와 `1LL * a * b`

`int`는 약 ±2.1×10^9까지만 담는다. **대입받는 변수가 `long long`이어도, 계산이 `int`끼리 이루어지면 이미 넘친다.**

```cpp
int a = 100000, b = 100000;
long long bad = a * b;          // int * int 가 먼저 계산되어 오버플로
long long good = 1LL * a * b;   // long long * int -> long long 으로 계산
long long also = (long long)a * b;
```

확인할 것: 값의 최댓값 × 개수(합), 값 × 값(곱), 쌍의 개수 N(N-1)/2.
10^5개 × 10^9 = 10^14, 쌍의 수 (2×10^5)²/2 = 2×10^10. 모두 `long long`이 필요하다.

`./ct asan <ID>`는 부호 있는 정수 오버플로를 런타임 오류로 잡아 준다.

## 2. 정수 나눗셈

```cpp
int a = 7, b = 2;
double bad = a / b;             // 3  (정수 나눗셈 후 3.0으로 변환)
double good = (double)a / b;    // 3.5
int mid = (lo + hi) / 2;        // 의도한 정수 나눗셈은 OK
```

- 음수의 나눗셈은 0 쪽으로 버린다: `-7 / 2 == -3`, `-7 % 2 == -1`.
- 음수의 나머지를 0 이상으로 만들려면 `((x % m) + m) % m`.
- 올림 나눗셈(양수): `(a + b - 1) / b`.

## 3. 부호 없는 `size()`와 `size() - 1`

`size()`의 반환형은 부호 없는 정수(`size_t`)다. 0에서 1을 빼면 음수가 아니라 **아주 큰 양수**가 된다.

```cpp
for (int i = 0; i < v.size() - 1; i++)   // v가 비어 있으면 0 - 1 = 18446744073709551615
    ...
for (int i = 0; i + 1 < (int)v.size(); i++)   // 고친 형태
int n = (int)v.size();                          // 가장 간단: 먼저 int로 받아 둔다
```

`int`와 `size_t`를 비교하면 `-Wall`이 경고한다. 경고를 무시하지 않는다.

## 4. 인덱스 범위와 `[begin, end)`

- 크기 N인 배열의 유효 인덱스는 **0 ~ N-1**. `a[N]`은 범위 밖이다.
- C++은 범위를 검사하지 않는다. 범위 밖 접근은 엉뚱한 값, 다른 변수의 오염, 런타임 오류 중 무엇이든 될 수 있다.
- STL의 구간은 모두 **반열린 구간** `[begin, end)`: `end`는 포함하지 않는다.

```cpp
vector<int> cnt(100);  cnt[100]++;         // 값의 범위가 0~100이면 크기는 101
for (int i = 0; i <= n; i++) a[i];         // 마지막에 a[n]
if (grid[nr][nc] == '#' || nr < 0) ...     // 범위 검사가 먼저 와야 한다
```

반열린 구간으로 통일하면 길이는 `r - l`, 비어 있는 조건은 `l == r`로 단순해진다.

## 5. 빈 컨테이너의 `front` / `back` / `top` / `pop`

비어 있을 때 호출하면 정의되지 않은 동작이다(오류 메시지 없이 이상하게 동작할 수 있다).

```cpp
int x = st.top();                 // 비어 있으면 위험
if (!st.empty()) { int x = st.top(); ... }
while (!q.empty()) { ... }
```

`vector`의 `back()`, `pop_back()`, `*min_element(...)`, `*v.begin()`도 마찬가지다.

## 6. `pop()`은 값을 반환하지 않는다

```cpp
int x = q.pop();       // 컴파일 오류: pop()의 반환형은 void
int x = q.front();     // 읽고
q.pop();               // 지운다
```

`stack`·`priority_queue`는 `top()`, `queue`는 `front()`.

## 7. `map` / `unordered_map`의 `[]`는 없는 키를 생성한다

```cpp
unordered_map<string, int> m;
if (m["kim"] > 0) { }             // "kim"이 값 0으로 생성된다. m.size()가 1 증가
if (m.count("kim")) { }           // 생성하지 않는다
auto it = m.find("kim");
if (it != m.end()) use(it->second);
```

문제가 되는 경우: 맵의 크기를 답으로 쓸 때, 조회가 매우 많아 불필요한 키가 쌓일 때, 순회 도중 `[]`로 조회할 때.
빈도를 세는 `m[key]++`는 의도한 사용이므로 괜찮다.

## 8. 비교 함수는 같은 값에 true를 반환하면 안 된다

`sort`의 비교 함수는 "a가 b보다 **엄격히** 앞"일 때만 true여야 한다.

```cpp
sort(v.begin(), v.end(), [](int a, int b) { return a >= b; });   // 잘못: a == b 일 때 true
sort(v.begin(), v.end(), [](int a, int b) { return a > b; });    // 올바름
```

`>=`를 쓰면 같은 값이 많은 입력에서 범위 밖 접근으로 런타임 오류가 날 수 있다(작은 입력에서는 우연히 통과하기도 한다).
다중 기준에서는 "다르면 그 기준으로 반환"하는 형태를 지킨다.

## 9. `unique`는 크기를 직접 줄이지 않는다

```cpp
sort(v.begin(), v.end());
unique(v.begin(), v.end());                          // v.size()는 그대로, 뒤에 쓰레기 값이 남는다
v.erase(unique(v.begin(), v.end()), v.end());        // 올바름
```

`unique`는 **연속한** 중복만 처리하므로 정렬이 선행되어야 한다.

## 10. `cin >>` 다음의 `getline`

`cin >> n`은 숫자 뒤의 줄바꿈을 입력에 남겨 둔다. 바로 다음 `getline`은 그 줄바꿈까지만 읽어 빈 문자열을 얻는다.

```cpp
cin >> n;
getline(cin, line);      // line == ""
cin >> n;
cin.ignore();            // 남은 줄바꿈 한 글자를 버린다
getline(cin, line);      // 올바름
```

공백 없는 토큰만 읽는 문제라면 `getline` 없이 `cin >>`만 쓰는 것이 가장 안전하다.

## 11. `endl`과 `'\n'`

`endl`은 줄바꿈 + **버퍼 비우기**다. 출력이 수만 줄이면 이것만으로 시간초과가 난다.

```cpp
cout << x << endl;    // 느림
cout << x << '\n';    // 빠름
```

입출력이 많은 문제에서는 `ios::sync_with_stdio(false); cin.tie(nullptr);`도 함께 쓴다.
이 두 줄을 쓴 뒤에는 `printf`/`scanf`와 섞어 쓰지 않는다.

## 12. 함수 인자의 복사와 참조

```cpp
long long sum(vector<int> v);            // 호출할 때마다 전체 복사: O(N)
long long sum(const vector<int> &v);     // 복사 없음

void fill_zero(vector<int> v) { for (int &x : v) x = 0; }    // 복사본만 바뀜. 원본 그대로
void fill_zero(vector<int> &v) { for (int &x : v) x = 0; }   // 원본 수정

for (auto x : big_strings) { }           // 원소마다 문자열 복사
for (const auto &x : big_strings) { }    // 복사 없음
for (int x : v) x *= 2;                  // v는 바뀌지 않는다 -> int &x
```

재귀 함수(DFS)에 `vector`를 값으로 넘기면 호출마다 복사되어 O(N²) 이상이 된다.

## 13. 재귀 깊이와 스택

재귀 호출은 호출마다 스택 메모리를 쓴다. 깊이가 수만~수십만이 되면 **스택 오버플로**(SIGSEGV)가 난다.
스택 크기는 환경마다 다르므로(보통 1~8MB) "내 컴퓨터에서는 됐다"가 통하지 않는다.

- 위험한 경우: 큰 격자의 재귀 DFS(한 줄로 길게 이어진 경로), N = 10^6인 재귀 DP.
- 대책: BFS(큐)나 명시적 스택을 쓰는 반복문, DP는 반복문으로 작은 것부터 채우기.
- 종료 조건이 빠진 재귀(무한 재귀)도 같은 증상으로 나타난다.

## 14. BFS는 큐에 넣을 때 방문 처리한다

```cpp
// 잘못: 꺼낼 때 방문 처리 -> 같은 칸이 여러 번 큐에 들어간다
while (!q.empty()) {
    auto cur = q.front(); q.pop();
    if (visited[cur]) continue;
    visited[cur] = true;
    for (next : 이웃) if (!visited[next]) q.push(next);
}

// 기본 패턴: 넣을 때 방문 처리
visited[start] = true; q.push(start);
while (!q.empty()) {
    auto cur = q.front(); q.pop();
    for (next : 이웃) {
        if (visited[next]) continue;
        visited[next] = true;          // 여기서 표시
        q.push(next);
    }
}
```

꺼낼 때 처리하는 방식은 답이 맞더라도 큐가 불필요하게 커져 시간·메모리 초과의 원인이 된다.
시작점의 방문 처리(`visited[start] = true`)를 빠뜨리는 실수도 흔하다.

## 15. 음수가 있는 배열과 구간 합 투 포인터

가변 길이 슬라이딩 윈도우는 "오른쪽을 늘리면 합이 커지고, 왼쪽을 줄이면 합이 작아진다"는 성질에 의존한다.
**음수가 있으면 이 성질이 깨져** 일반적인 구간 합 투 포인터가 성립하지 않을 수 있다.

반례: `[4, 5, -8, 1]`에서 합이 2 이하인 가장 긴 구간. 정답은 전체(합 2, 길이 4)지만,
윈도우 방식은 `4 + 5 = 9 > 2`에서 왼쪽을 버려 전체 구간을 영영 보지 못한다.

대안: 누적합 + 해시([05단원](../units/05-prefix-sum/README.md)), 또는 문제에 맞는 다른 방법.
투 포인터를 쓰기 전에 **입력 제한에서 원소가 양수인지** 확인한다.

## 16. 그리디는 정당화 또는 반례 검토가 필요하다

"가장 ~한 것부터"라는 기준은 그럴듯해 보여도 틀린 경우가 많다.

- 동전 {1, 3, 4}로 6 만들기: 큰 것부터 → 4+1+1(3개), 최적은 3+3(2개).
- 회의실 배정: 시작이 빠른 것부터, 짧은 것부터 → 모두 반례 있음. 끝이 빠른 것부터가 정답.

제출 전에 (1) 원소 3~4개짜리 반례를 직접 찾아보고, (2) "최적해의 선택을 내 선택으로 바꿔도 손해가 없다"는
교환 논법으로 설명되는지 확인한다. 둘 다 안 되면 완전탐색이나 DP를 검토한다([10단원](../units/10-greedy/README.md)).

## 그 밖에 자주 보는 것들

| 실수 | 설명 |
|---|---|
| 변수 초기화 누락 | 지역 변수 `int sum;`의 초기값은 쓰레기 값이다. `int sum = 0;` |
| `=`와 `==` | `if (x = 5)`는 대입이며 항상 참 |
| 최솟값의 초기값 | `int best = 0;`으로 시작하면 양수들의 최솟값이 0으로 남는다. 첫 원소나 충분히 큰 값으로 |
| 최댓값의 초기값 | 음수가 있을 수 있는데 0으로 시작 |
| `2^N`을 `2 ^ N`으로 작성 | `^`는 XOR. `1 << N` 또는 반복 곱셈 |
| `char`와 `string` 비교 | `s[i] == "a"`는 오류. `s[i] == 'a'` |
| 전역/정적 배열 크기 | `int a[1000000][100];`은 메모리 초과. 필요한 크기를 계산한다 |
| `mid = (lo + hi) / 2` | 값이 클 때 오버플로 → `lo + (hi - lo) / 2` |
| 나머지 연산을 마지막에만 | 중간 오버플로. 더하거나 곱할 때마다 `% MOD` |
| 실수 비교 | `double`의 `==` 비교는 피하고, 가능하면 정수로 계산 |
| 디버그 출력 방치 | 제출 전 `cout` 디버그 문장 제거 |
| 테스트 케이스 간 초기화 누락 | 여러 케이스를 반복 처리할 때 배열·변수를 매번 초기화 |
