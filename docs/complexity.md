# 복잡도 가이드

## 시간복잡도란

입력 크기 N이 커질 때 **연산 횟수가 어떤 비율로 늘어나는가**를 나타낸다. O(N²)은 N이 10배가 되면 연산이 약 100배가 된다는 뜻이다.
상수 배와 낮은 차수 항은 무시한다(3N² + 5N → O(N²)).

## 입력 크기별로 검토할 복잡도

기준: 단순 연산 약 10^8번을 1초 안팎으로 어림한다.

| N의 최댓값 | 시도할 만한 복잡도 | N이 최댓값일 때 연산 수 | 대표 방법 |
|---|---|---|---|
| ≤ 10 | O(N!), O(N! × N) | 10! ≈ 3.6×10^6 | 모든 순열 |
| ≤ 20 | O(2^N), O(2^N × N) | 2^20 ≈ 10^6 | 모든 부분집합 |
| ≤ 100 | O(N⁴) | 10^8 | 사중 반복문(드묾) |
| ≤ 500 | O(N³) | 1.25×10^8 | 삼중 반복문 |
| ≤ 5,000 | O(N²) | 2.5×10^7 | 모든 쌍, 2차원 DP |
| ≤ 200,000 | O(N log N) | 약 3.5×10^6 | 정렬, 이분탐색, 힙, map/set |
| ≤ 1,000,000 | O(N) | 10^6 | 한 번 훑기, 누적합, 투 포인터, 해시, BFS |
| ≤ 10^9 이상 | O(log N), O(√N), O(1) | 30 / 3×10^4 | 답에 대한 이분탐색, 수식 |

격자는 칸의 수 H×W를 N으로 본다(1000×1000 = 10^6).

### 이 표를 읽을 때 주의할 점

- **어림값이다.** 실제 실행 시간은 채점 환경(CPU, 컴파일 옵션), 시간제한, 그리고 **연산의 종류**에 따라 크게 달라진다.
  - 배열을 순서대로 읽는 덧셈은 10^8번이 0.1초도 안 걸릴 수 있다.
  - `unordered_map` 조회, `map`/`set` 연산, 문자열 복사, 나눗셈·나머지, 캐시를 벗어나는 메모리 접근은 한 번이 수십 배 느리다.
  - 그래서 같은 O(N log N)이라도 `sort`한 `vector`가 `set`보다 훨씬 빠르다.
- 10^8에 가까우면 "될 수도, 안 될 수도" 있는 영역이다. 더 나은 복잡도가 있는지 한 번 더 생각한다.
- 10^9 이상이면 단순 연산이라도 대개 시간초과다.
- **`2^N`과 `N!`을 혼동하지 않는다.**

| N | 2^N | N! |
|---|---|---|
| 8 | 256 | 40,320 |
| 10 | 1,024 | 3,628,800 |
| 12 | 4,096 | 479,001,600 |
| 15 | 32,768 | 약 1.3×10^12 |
| 20 | 1,048,576 | 약 2.4×10^18 |

부분집합(고른다/안 고른다)은 2^N, 순서를 정하는 것은 N!이다. N=12에서 부분집합은 여유롭지만 순열은 이미 위험하다.

## 자주 쓰는 연산의 복잡도

| 연산 | 복잡도 |
|---|---|
| 배열 인덱스 접근, `push_back`, 스택/큐 push·pop | O(1) |
| `unordered_map`/`unordered_set` 삽입·조회 | 평균 O(1) (상수 큼) |
| `map`/`set` 삽입·조회, `priority_queue` push·pop, 이분탐색 | O(log N) |
| 배열 순회, `find`, `count`, `accumulate`, `reverse`, `unique` | O(N) |
| `vector` 중간 삽입·삭제 | O(N) |
| `sort` | O(N log N) |
| BFS/DFS | O(V + E), 격자는 O(H×W) |
| 문자열 비교·복사·`substr` | O(길이) |

## 반복문에서 복잡도 읽기

```cpp
for (i = 0; i < n; i++)             // O(N)

for (i = 0; i < n; i++)
    for (j = 0; j < n; j++)         // O(N²)

for (i = 0; i < n; i++)
    for (j = i + 1; j < n; j++)     // N(N-1)/2 -> O(N²)

for (i = 1; i < n; i *= 2)          // O(log N): 두 배씩 증가

for (i = 0; i < n; i++)
    sort(...)                       // O(N × N log N): 반복문 안의 함수 비용을 곱한다

for (right = 0; right < n; right++)
    while (조건) left++;            // O(N): left는 전체를 통틀어 최대 N번만 증가
```

마지막 예처럼 중첩되어 보여도, 안쪽 반복문의 **총 실행 횟수**가 N 이하이면 전체는 O(N)이다(투 포인터, BFS).

숨은 비용에 주의: 반복문 안에서 `v.erase(v.begin())`, `find(v.begin(), v.end(), x)`, `s.substr(...)`,
`vector`의 값 전달은 각각 O(N)이다.

## 공간복잡도

| 자료 | 메모리 |
|---|---|
| `int` 10^6개 | 약 4MB |
| `long long` 10^6개 | 약 8MB |
| `int` 5000×5000 2차원 배열 | 약 100MB (위험) |
| `vector<bool>` 10^6개 | 약 0.125MB |
| `unordered_map<int,int>` 10^6개 | 수십 MB (원소당 오버헤드가 큼) |

메모리 제한은 문제마다 다르다. 2차원 배열을 만들기 전에 `행 × 열 × 원소 크기`를 계산해 본다.

## 자료형 선택

| 값의 크기 | 자료형 |
|---|---|
| ~ 2×10^9 | `int` |
| ~ 9×10^18 | `long long` |
| 그 이상 | 문제에서 나머지 연산을 요구하거나, 다른 접근이 필요 |

제한을 보고 **최악의 경우를 직접 계산**한다: "값 최대 10^9 × 개수 최대 2×10^5 = 2×10^14 → `long long`".
확신이 없으면 `long long`을 쓴다. 기초 범위에서 `long long`을 써서 손해 보는 경우는 거의 없다.
