## 개념

**DP(동적 계획법)**는 큰 문제의 답을 **작은 문제의 답으로부터 계산**하고, 한 번 계산한 답은 **저장해 두고 다시 쓰는** 방법이다.

계단을 1칸 또는 2칸씩 오를 때 n번 칸에 가는 방법의 수를 재귀로 구하면

```
f(5) = f(4) + f(3)
f(4) = f(3) + f(2)      ← f(3)을 또 계산
f(3) = f(2) + f(1)      ← f(2)를 또 계산 ...
```

같은 계산이 지수적으로 반복된다(f(30)에 약 270만 번 호출). 작은 것부터 **표에 채워 가면** 29번의 덧셈으로 끝난다.

### DP 설계의 네 가지 요소

| 요소 | 질문 | 계단 예 |
|---|---|---|
| **상태** | 표의 칸 하나가 무엇을 뜻하는가? | `ways[i]` = i번 칸에 도착하는 방법의 수 |
| **점화식** | 그 칸을 더 작은 칸들로 어떻게 구하는가? | `ways[i] = ways[i-1] + ways[i-2]` |
| **초기값** | 점화식을 쓸 수 없는 가장 작은 칸의 값은? | `ways[0] = 1, ways[1] = 1` |
| **계산 순서** | 필요한 칸이 항상 먼저 채워지는가? | i를 2부터 n까지 증가 |

**상태를 한 문장으로 정확히 쓰는 것**이 가장 중요하다. 상태 정의가 모호하면 점화식도 틀린다.

### 점화식을 찾는 요령: "마지막 한 걸음"

"i번 칸에 도착하기 **바로 직전**에는 어디에 있었는가?"를 묻는다.
가능한 직전 위치들을 빠짐없이, 겹치지 않게 나열하면 그것이 점화식이다.

- 경우의 수: 직전 경우들의 **합**
- 최댓값/최솟값: 직전 경우들 중 **가장 좋은 것** + 현재 칸의 값

### 세 가지 기본형

```cpp
// (1) 계단: 방법의 수
ways[i] = ways[i-1] + ways[i-2];

// (2) 격자 경로 수: 오른쪽/아래로만 이동
paths[r][c] = paths[r-1][c] + paths[r][c-1];      // 막힌 칸은 0

// (3) 격자 최대 합
best[r][c] = max(best[r-1][c], best[r][c-1]) + v[r][c];
```

## 이런 문제에서 떠올린다

| 문제의 특징 | 떠올릴 것 |
|---|---|
| "방법의 수", "경우의 수" (+ "1,000,000,007로 나눈 나머지") | DP (합) |
| "최대/최소 합", 선택이 이후 선택에 영향을 줌 | DP (max/min) |
| 그리디 기준의 반례가 쉽게 나온다 | DP |
| 완전탐색하면 같은 상황이 반복해서 나온다 | 그 "상황"이 곧 상태 |
| 격자에서 오른쪽/아래로만 이동 | 2차원 DP |
| 순서대로 놓인 것들을 앞에서부터 결정 | `dp[i]` = 앞 i개까지 고려한 답 |

## 작은 입력으로 따라가기

**격자 경로 수** (`#`은 막힌 칸)

```
. . . .        1 1 1 1
. # . .   →    1 0 1 2
. . . .        1 1 2 4
```

- 첫 행·첫 열은 올 수 있는 방향이 하나뿐이라 모두 1.
- (1,1)은 막힌 칸이라 0.
- (1,2) = 위 1 + 왼쪽 0 = 1, (1,3) = 위 1 + 왼쪽 1 = 2
- (2,2) = 위 1 + 왼쪽 1 = 2, (2,3) = 위 2 + 왼쪽 2 = 4

**이웃하지 않게 골라 최대 합**: `a = [6, 7, 1, 30, 8, 2, 4]`,
`best[i] = max(best[i-1], best[i-2] + a[i-1])`

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| a[i-1] | - | 6 | 7 | 1 | 30 | 8 | 2 | 4 |
| best | 0 | 6 | 7 | 7 | 37 | 37 | 39 | 41 |

"큰 것부터 고르기" 같은 그리디가 아니라, 각 위치에서 "고른다/안 고른다" 두 경우를 모두 비교한 결과다.

## 복잡도

**(상태의 수) × (상태 하나를 계산하는 비용)**

| 문제 | 상태 수 | 상태당 | 전체 |
|---|---|---|---|
| 계단 | N | O(1) | O(N) |
| 격자 | H×W | O(1) | O(H×W) |

공간은 표의 크기(O(N), O(H×W)). 직전 몇 칸만 쓰는 점화식은 변수 몇 개로 줄일 수 있지만, 처음에는 표 전체를 두는 편이 디버깅하기 쉽다.

## 자주 하는 실수와 반례

| 실수 | 반례 / 증상 |
|---|---|
| 상태 정의 없이 점화식부터 작성 | 인덱스가 1 어긋나거나 의미가 섞임 |
| 초기값 오류 (`ways[0] = 0`) | 모든 값이 0 |
| `i-2`, `r-1` 등의 범위 검사 누락 | 음수 인덱스 접근 |
| 격자 밖을 0으로 취급하고 `max` | 값이 음수일 때 격자 밖의 0을 선택 (1×4 격자 `1 -2 3 -4` → -2가 아닌 값) |
| 최댓값 표를 0으로 초기화 | 모든 값이 음수인 입력에서 오답 |
| 경우의 수를 마지막에만 `% MOD` | 중간에 오버플로 |
| 나머지끼리의 합·곱을 `int`로 | `(10^9+6) × 3`은 `int` 초과 → `long long`에 계산 |
| 메모 없는 재귀 | N=50만 되어도 끝나지 않음 |
| 계산 순서가 점화식과 맞지 않음 | 아직 채워지지 않은 칸을 참조 |
| 깊은 재귀(메모이제이션) | N=10^6에서 스택 오버플로 → 반복문으로 |
