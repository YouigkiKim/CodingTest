## 학습 목표

- `vector`와 `string`을 선언하고, 인덱스로 읽고 쓰고, 순회한다.
- 값을 인덱스로 쓰는 **빈도 배열**로 개수를 센다.
- 문제에 적힌 규칙을 그대로 코드로 옮기는 **구현(시뮬레이션)** 문제를 방향 배열로 깔끔하게 푼다.

## 개념

### vector - 크기가 변하는 배열

```cpp
#include <vector>
vector<int> a(n);          // 크기 n, 모두 0
vector<int> b(n, -1);      // 크기 n, 모두 -1
a[0] = 5;                  // 인덱스는 0 ~ n-1
a.push_back(7);            // 뒤에 추가
int len = (int)a.size();   // 원소 수
vector<vector<int>> g(h, vector<int>(w, 0));  // h행 w열 2차원 배열
```

유효한 인덱스는 **0부터 size()-1까지**다. `a[n]`은 범위 밖이며, C++은 이를 막아 주지 않는다(엉뚱한 값 또는 런타임 오류).

### string - 문자의 배열

```cpp
#include <string>
string s = "hello";
char c = s[1];             // 'e'
s += "!";                  // 이어 붙이기
int idx = s[0] - 'a';      // 'h' - 'a' = 7  (문자를 0~25 숫자로)
int d = '7' - '0';         // 숫자 문자를 정수로 -> 7
```

문자는 내부적으로 정수다. `'a'`~`'z'`가 연속한 값이라는 점을 이용해 `ch - 'a'`로 0~25를 만든다.

### 빈도 배열

"각 값이 몇 번 나왔는가?"를 셀 때, 값의 범위가 작으면 **값을 인덱스로 쓰는 배열**을 만든다.

```cpp
vector<int> cnt(26, 0);
for (char ch : s) cnt[ch - 'a']++;
```

### 구현(시뮬레이션)과 방향 배열

격자에서 움직이는 문제는 방향별 이동량을 배열에 넣어 두면 `if`를 방향마다 쓰지 않아도 된다.

```cpp
const int dr[4] = {-1, 1, 0, 0};   // 위, 아래, 왼쪽, 오른쪽
const int dc[4] = {0, 0, -1, 1};
int nr = r + dr[d], nc = c + dc[d];
if (nr < 0 || nr >= h || nc < 0 || nc >= w) { /* 격자 밖 */ }
```

행 번호는 **아래로 갈수록 커진다**(위로 이동 = 행 -1). 수학의 y축과 반대라 자주 헷갈린다.

## 이런 문제에서 떠올린다

| 문제의 특징 | 떠올릴 것 |
|---|---|
| "가장 많이 나온", "몇 번 등장", 값의 범위가 작다(0~100, 알파벳) | 빈도 배열 |
| "명령을 차례로 수행", "규칙에 따라 이동/변경" | 시뮬레이션, 상태 변수를 먼저 정한다 |
| 격자, 상하좌우 | 방향 배열 + 범위 검사 |
| 문자 종류별 처리, 대소문자, 숫자 문자 | `ch - 'a'`, `ch - '0'` |

## 작은 입력으로 따라가기

**빈도 배열**: 점수 `70 80 70 90 80`에서 최빈값(동률이면 작은 값) 찾기

| 읽은 값 | cnt[70] | cnt[80] | cnt[90] |
|---|---|---|---|
| 70 | 1 | 0 | 0 |
| 80 | 1 | 1 | 0 |
| 70 | 2 | 1 | 0 |
| 90 | 2 | 1 | 1 |
| 80 | 2 | 2 | 1 |

이후 0부터 100까지 훑으며 `cnt[s] > cnt[best]`일 때만 갱신 → 70에서 best=70(2회), 80은 2회로 같으므로 갱신 안 함 → 답 70.

**시뮬레이션**: 3×3 격자, (0,0)에서 명령 `R R D`

| 명령 | 다음 칸 계산 | 범위 안? | 위치 |
|---|---|---|---|
| R | (0, 1) | O | (0, 1) |
| R | (0, 2) | O | (0, 2) |
| D | (1, 2) | O | (1, 2) |

"다음 칸을 먼저 계산 → 검사 → 통과하면 이동"의 세 단계를 항상 지킨다.

## 복잡도

| 연산 | 시간 | 이유 |
|---|---|---|
| `v[i]`, `v.back()`, `v.size()` | O(1) | 위치를 바로 계산 |
| `v.push_back(x)` | 평균 O(1) | 가끔 재할당하지만 평균적으로 상수 |
| 맨 앞/중간 삽입·삭제 (`insert`, `erase`) | O(N) | 뒤 원소를 모두 밀어야 함 |
| 전체 순회, 빈도 세기 | O(N) | 원소마다 한 번 |
| `s.substr(pos, len)` | O(len) | 새 문자열을 만든다 |
| 시뮬레이션 | O(단계 수 × 단계당 비용) | 단계당 비용이 O(1)이 되게 설계 |

공간은 저장하는 원소 수에 비례한다. 빈도 배열은 O(값의 범위).

## 자주 하는 실수와 반례

| 실수 | 반례 / 증상 |
|---|---|
| 빈도 배열 크기를 값의 최댓값으로 잡음 (`cnt(100)`) | 값 100이 들어오면 범위 밖 접근 |
| `for (int i = 0; i <= n; i++) a[i]` | 마지막에 `a[n]` 접근 |
| `i < v.size() - 1`에서 `v`가 비어 있음 | `size()`는 부호 없는 정수라 `0 - 1`이 매우 큰 수가 된다 → `(int)v.size()` 또는 `i + 1 < v.size()` |
| 범위 검사보다 `grid[nr][nc]` 접근이 먼저 | 격자 밖 접근 |
| 위쪽을 `dr = +1`로 둠 | 반대로 움직임 |
| 음수의 나머지 (`(dir - 1) % 4`) | `-1 % 4 == -1` → `(dir + 3) % 4` |
| 동률 규칙 무시 | "여러 개면 가장 작은 것" 조건을 놓침 |

메모리 접근 오류가 의심되면 `./ct asan <문제ID>`로 실행하면 어느 줄에서 범위를 벗어났는지 알려 준다.
