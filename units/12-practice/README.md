# 12 실전 연습

이전: [11 DP 기초](../11-dp/README.md) · [전체 목차](../../README.md) · [치트시트](../../docs/cheatsheet.md) · [복잡도 가이드](../../docs/complexity.md)

예상 소요: 3~4시간(모의시험 2회 포함) · 문제: [모의시험 1](../../exams/exam1/README.md), [모의시험 2](../../exams/exam2/README.md)

## 학습 목표

- 문제를 읽고 **입력 제한에서 출발해** 알고리즘을 고른다.
- 제출 전에 경계조건을 스스로 점검한다.
- 60분·4문제 형식에서 시간을 배분하고, 시험 후 회고로 약점을 찾는다.

## 선행 지식

00~11단원 전체.

## 1. 문제를 푸는 순서

매 문제에서 같은 순서를 반복한다. 급할수록 순서를 건너뛰지 않는다.

1. **끝까지 읽는다.** 출력 형식, "없으면 -1", "여러 개면 가장 작은 것" 같은 조건에 밑줄.
2. **제한을 본다.** N의 최댓값 → 허용되는 복잡도. 값의 최댓값 → 자료형.
3. **예제를 손으로 푼다.** 내가 문제를 제대로 이해했는지 확인하는 가장 빠른 방법.
4. **방법을 정한다.** 아래 표를 사용. 가장 단순한 방법이 제한 안에 들어오면 그것을 쓴다.
5. **구현한다.** 입력 → 처리 → 출력. 변수 이름은 뜻이 드러나게.
6. **검증한다.** 예제 + 직접 만든 경계 입력.

## 2. 제한에서 복잡도로

| N의 최댓값 | 시도할 만한 복잡도 | 대표 방법 |
|---|---|---|
| ≤ 10 | O(N!) | 순열 전부 |
| ≤ 20 | O(2^N × N) | 부분집합 전부 |
| ≤ 500 | O(N³) | 삼중 반복문 |
| ≤ 5,000 | O(N²) | 모든 쌍, 2차원 DP |
| ≤ 200,000 | O(N log N) | 정렬, 이분탐색, 힙, map |
| ≤ 1,000,000 | O(N) | 한 번 훑기, 누적합, 투 포인터, 해시, 1차원 DP |
| 10^9 이상 | O(log N) 또는 O(1) | 답에 대한 이분탐색, 수식 |

실행 시간은 환경과 연산의 종류에 따라 달라지므로 어림값이다. 자세한 설명은 [복잡도 가이드](../../docs/complexity.md).

## 3. 문제의 신호에서 방법으로

| 문제에서 보이는 것 | 먼저 떠올릴 것 | 단원 |
|---|---|---|
| 규칙대로 움직이기, 명령 수행 | 시뮬레이션 | [01](../01-array-string/README.md) |
| 개수 세기, 가장 많이 나온 것 | 빈도 배열 / 해시맵 | [01](../01-array-string/README.md), [04](../04-hash-set/README.md) |
| 순서대로 출력, 여러 기준의 순위 | 정렬 + 비교 함수 | [02](../02-sorting/README.md) |
| N이 아주 작다 | 완전탐색 | [03](../03-brute-force/README.md) |
| 존재 여부, 중복, "두 개를 골라 합이 K" | 해시 | [04](../04-hash-set/README.md) |
| 구간의 합을 여러 번, 합이 K인 구간 | 누적합 (+해시) | [05](../05-prefix-sum/README.md) |
| 괄호, 가장 최근 것 | 스택 | [06](../06-stack-queue-heap/README.md) |
| 가장 작은/큰 것을 반복해서 꺼내기 | 우선순위 큐 | [06](../06-stack-queue-heap/README.md) |
| "가능한 최댓값/최솟값", 답의 범위가 큼 | 답에 대한 이분탐색 | [07](../07-binary-search/README.md) |
| 정렬된 배열의 두 수, 양수 배열의 연속 구간 | 투 포인터 / 윈도우 | [08](../08-two-pointers/README.md) |
| 격자, 연결된 영역, 최소 이동 횟수 | BFS | [09](../09-bfs-dfs/README.md) |
| 최대한 많이 고르기 + 정렬 기준 | 그리디 (반례 확인) | [10](../10-greedy/README.md) |
| 방법의 수, 선택이 이어지는 최대/최소 | DP | [11](../11-dp/README.md) |

하나의 문제가 두 가지를 섞어 쓰는 경우도 많다(정렬 + 그리디, 누적합 + 해시, 정렬 + 이분탐색).

## 4. 제출 전 경계조건 점검표

직접 입력을 만들어 `./ct run <ID>`로 넣어 본다.

- [ ] **최소 크기**: N = 1 (또는 문제의 최솟값). 빈 결과.
- [ ] **모두 같은 값**: 동률 처리, 중복 처리.
- [ ] **최댓값**: 합·곱·개수가 `int`를 넘는가? → `long long`
- [ ] **답이 없는 경우**: -1, 0, 빈 출력 등 문제가 요구하는 형식.
- [ ] **음수**: 초깃값을 0으로 두지 않았는가? 나머지 연산이 음수가 되지 않는가?
- [ ] **경계 인덱스**: 첫 원소, 마지막 원소, `i-1`, `i+1`, 격자의 가장자리.
- [ ] **이미 정렬됨 / 역순**: 정렬을 가정했다면 실제로 정렬했는가?
- [ ] **출력 형식**: 공백·줄바꿈, 대소문자(`YES`/`Yes`), 디버그 출력 제거.

오류 유형별 대처:

| 판정 | 먼저 의심할 것 | 도구 |
|---|---|---|
| WA(오답) | 경계조건, 오버플로, 문제 오독 | 실패 입력을 손으로 따라가기 |
| TLE(시간초과) | 복잡도, 불필요한 복사, `endl`, 무한 루프 | 제한으로 연산 횟수 계산 |
| RE(런타임 오류) | 범위 밖 인덱스, 빈 컨테이너 접근, 0으로 나누기, 깊은 재귀 | `./ct asan <ID>` |
| CE(컴파일 오류) | 헤더 누락, 세미콜론, 자료형 불일치 | 첫 번째 오류 메시지부터 읽기 |

## 5. 60분·4문제 시간 배분

실제 시험의 구성과 난이도는 시험마다 다르다. 아래는 이 코스의 모의시험을 위한 **연습용 기준**이다.

| 시간 | 할 일 |
|---|---|
| 0~5분 | 네 문제를 모두 훑어보고 쉬운 순서를 정한다. 각 문제의 제한에 표시. |
| 5~15분 | 가장 쉬운 문제를 푼다(목표 10분). |
| 15~30분 | 두 번째 문제(목표 15분). |
| 30~55분 | 남은 두 문제. 한 문제에 15분 이상 진전이 없으면 다른 문제로 넘어간다. |
| 55~60분 | 새 코드를 쓰지 않는다. 제출한 풀이의 경계조건을 재점검한다. |

원칙:

- **쉬운 문제를 확실히** 맞히는 것이 어려운 문제를 붙잡고 있는 것보다 낫다.
- 완전한 풀이가 떠오르지 않으면 **단순한 풀이(완전탐색)라도** 작성한다. 부분 점수가 있을 수 있고, 검증용으로도 쓸 수 있다.
- 막혔을 때는 제한을 다시 읽는다. 풀이의 힌트는 대부분 제한에 있다.

## 6. 모의시험 진행

```bash
./ct exam 1            # 문제 목록과 파일 위치 확인 → 타이머 60분 시작
./ct test e1a          # 풀면서 문제별 채점
./ct exam 1 --grade    # 종료 후 4문제 일괄 채점
```

1. [모의시험 1](../../exams/exam1/README.md) - 구현·문자열·정렬·해시·누적합 중심
2. [모의시험 2](../../exams/exam2/README.md) - 이분탐색·탐색·그리디·DP 혼합
3. 각 시험이 끝나면 [회고 양식](../../exams/retrospective-template.md)을 복사해 작성한다.
4. 못 푼 문제는 힌트 → 재도전 → 해설 순서로 본다. 해설을 읽은 문제는 며칠 뒤 **빈 파일에서 다시** 풀어 본다.

두 시험 사이에는 간격을 두고, 첫 시험의 회고에서 나온 약점 단원을 복습한 뒤 두 번째 시험을 본다.

## 완료 체크리스트

- [ ] "제한 → 복잡도" 표와 "신호 → 방법" 표를 보지 않고 대략 재현할 수 있다.
- [ ] 경계조건 점검표를 습관적으로 적용한다.
- [ ] 모의시험 1을 60분 안에 치르고 회고를 작성했다.
- [ ] 모의시험 2를 60분 안에 치르고 회고를 작성했다.
- [ ] 두 회고에서 반복된 실수 유형을 세 가지 이내로 정리했다.
- [ ] 못 푼 문제를 해설 없이 다시 풀어 통과했다.
