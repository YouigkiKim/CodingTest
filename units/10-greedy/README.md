## 개념

**그리디(탐욕법)**는 매 단계에서 "지금 가장 좋아 보이는 선택"을 하고, 그 선택을 **번복하지 않는** 방법이다.
구현은 보통 "정렬 → 한 번 훑기"로 매우 짧다. 어려운 것은 코드가 아니라 **그 선택 기준이 정말 최적인가**이다.

그리디는 틀리기 쉽다. 그럴듯한 기준이 여러 개 있고, 대부분은 틀린다.

### 그리디를 쓰기 전 확인 절차

1. **기준 후보를 여러 개 떠올린다.** (가장 작은 것부터? 가장 빨리 끝나는 것부터? 비율이 좋은 것부터?)
2. **작은 반례를 찾는다.** 원소 3~4개짜리 입력을 손으로 만들어 각 기준을 깨뜨려 본다.
   손으로 어렵다면 완전탐색을 짜서 무작위 작은 입력으로 비교한다(예제 코드 참고).
3. **살아남은 기준을 정당화한다.** 가장 흔한 논법은 **교환 논법**이다:
   "최적해가 내 선택과 다르게 골랐더라도, 그것을 내 선택으로 **바꿔도 손해가 없다**."
4. 반례도 못 찾고 정당화도 못 하겠다면, 그리디가 아니라 완전탐색이나 DP([11단원](../11-dp/README.md))를 의심한다.

### 대표 문제: 회의실 배정

회의 N개의 `[시작, 끝)`이 주어진다. 회의실이 하나일 때, 겹치지 않게 **최대 몇 개**를 열 수 있는가?

| 기준 | 반례 | 결과 |
|---|---|---|
| 일찍 시작하는 것부터 | `[0,10) [1,2) [3,4)` | 1개 (정답 2개) |
| 짧은 것부터 | `[0,5) [4,6) [5,10)` | 1개 (정답 2개) |
| **일찍 끝나는 것부터** | - | 항상 최적 |

정당화: 가장 일찍 끝나는 회의 A를 고르지 않은 최적해가 있다고 하자. 그 최적해의 첫 회의 B를 A로 바꿔도,
A가 B보다 늦게 끝나지 않으므로 나머지 회의와 겹치지 않는다. 개수는 그대로다. 즉 A를 고르는 것은 손해가 아니다.
남은 회의들에 대해 같은 논리를 반복한다.

```cpp
sort(끝나는 시각 오름차순);
int count = 0, last_end = (아주 작은 값);
for (각 회의 m)
    if (m.start >= last_end) { count++; last_end = m.end; }
```

## 이런 문제에서 떠올린다

| 문제의 특징 | 떠올릴 것 |
|---|---|
| "최대한 많이 고르기", "최소 개수로 덮기" + 정렬 기준이 보임 | 그리디 후보 |
| 구간(시작, 끝)들을 다루는 최적화 | 끝점 기준 정렬을 먼저 시도 |
| 모든 항목의 "가치"가 같고 "비용"만 다르다 | 비용이 작은 것부터 |
| N이 커서(10만 이상) 완전탐색·DP가 불가능 | 정렬 기반 그리디일 가능성 |
| 선택이 **이후의 선택지에 복잡한 영향**을 준다 | 그리디가 틀릴 가능성이 높다 → DP 검토 |

그리디가 **실패하는** 대표 예: 동전 {1, 3, 4}로 6을 만들 때 "큰 동전부터"는 4+1+1(3개), 최적은 3+3(2개).

## 작은 입력으로 따라가기

회의 `[1,4) [3,5) [0,6) [5,7) [3,8) [5,9) [6,10) [8,11)` (이미 끝나는 시각 순)

| 회의 | 시작 ≥ last_end? | 선택 | last_end |
|---|---|---|---|
| [1,4) | (처음) | O | 4 |
| [3,5) | 3 ≥ 4 ✗ | | 4 |
| [0,6) | 0 ≥ 4 ✗ | | 4 |
| [5,7) | 5 ≥ 4 ✓ | O | 7 |
| [3,8) | ✗ | | 7 |
| [5,9) | ✗ | | 7 |
| [6,10) | ✗ | | 7 |
| [8,11) | 8 ≥ 7 ✓ | O | 11 |

3개. 완전탐색 결과와 일치한다(예제 실행 결과 참고).

## 복잡도

- 대부분 O(N log N): 정렬이 지배적이고, 그 뒤는 한 번 훑는 O(N).
- 공간 O(N).

## 자주 하는 실수와 반례

| 실수 | 반례 / 증상 |
|---|---|
| 떠오른 첫 기준을 검증 없이 제출 | 위의 표 참고 |
| 끝점이 맞닿는 경우의 처리 (`>=` vs `>`) | `[1,3) [3,5)`는 겹치지 않음. 닫힌 구간 `[1,3] [3,5]`는 겹침. **문제의 구간 정의를 확인** |
| `last_end` 초깃값을 0으로 | 시각/좌표가 음수일 수 있으면 틀림 → "아직 없음" 플래그 사용 |
| 개수 최대화와 합 최대화를 혼동 | "가장 많은 회의"와 "가장 긴 총 회의 시간"은 다른 문제 |
| 그리디가 안 되는 문제에 적용 | 동전 {1,3,4}, 금액 6 |
| 합을 `int`로 | 무게·비용 합이 21억 초과 |
