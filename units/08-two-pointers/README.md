# 08 투 포인터·슬라이딩 윈도우

이전: [07 이분탐색](../07-binary-search/README.md) · 다음: [09 BFS·DFS](../09-bfs-dfs/README.md) · [전체 목차](../../README.md) · [치트시트](../../docs/cheatsheet.md)

예상 소요: 3시간 · 문제: [08a 가장 가까운 합](../../problems/08a-closest-pair-sum/problem.md), [08b 가장 짧은 구간](../../problems/08b-shortest-segment/problem.md)

## 학습 목표

- 정렬된 배열의 양 끝에서 좁혀 오는 투 포인터로 두 수의 합 문제를 O(N)에 푼다.
- 고정 길이 구간의 합을 한 칸씩 밀면서 O(1)에 갱신한다.
- 양수 배열에서 조건에 따라 늘었다 줄었다 하는 구간을 관리하고, 그 방법이 성립하는 조건을 설명한다.

## 선행 지식

[02단원](../02-sorting/README.md): 정렬. [05단원](../05-prefix-sum/README.md): 구간 합.

## 개념

**투 포인터**는 두 개의 인덱스를 **되돌아가지 않고 한 방향으로만** 움직여, 이중 반복문(O(N²))을 O(N)으로 줄이는 기법이다.
포인터를 움직일 때 "버려지는 후보들은 답이 될 수 없다"는 근거가 있어야 한다.

### 1. 양 끝에서 좁히기 (정렬된 배열, 두 수의 합)

```cpp
int left = 0, right = n - 1;
while (left < right) {
    long long sum = a[left] + a[right];
    if (sum == target) { /* 찾음 */ break; }
    if (sum < target) left++;    // 합을 키워야 한다
    else right--;                // 합을 줄여야 한다
}
```

근거: 합이 작으면, `a[left]`는 가장 큰 상대(`a[right]`)와 짝지어도 모자라므로 더 볼 필요가 없다.

### 2. 고정 길이 슬라이딩 윈도우

길이 k인 구간을 오른쪽으로 한 칸 밀면 **한 원소가 들어오고 한 원소가 나간다.** 합을 처음부터 다시 구할 필요가 없다.

```cpp
window += a[right];        // 들어오는 원소
window -= a[right - k];    // 나가는 원소
```

### 3. 가변 길이 윈도우 (양수 배열)

```cpp
int left = 0; long long sum = 0;
for (int right = 0; right < n; right++) {
    sum += a[right];                 // 오른쪽을 늘린다
    while (조건이 깨졌거나/만족하는 동안) {
        ...                          // 필요하면 답 갱신
        sum -= a[left]; left++;      // 왼쪽을 줄인다
    }
}
```

이 방법은 **원소가 모두 양수(또는 0 이상)**일 때 성립한다. 그래야 "오른쪽을 늘리면 합이 커지고, 왼쪽을 줄이면 합이 작아진다"는 단조성이 생긴다.

## 이런 문제에서 떠올린다

| 문제의 특징 | 떠올릴 것 |
|---|---|
| 정렬된 배열 + "두 수의 합이 ~", "가장 가까운 합" | 양 끝 투 포인터 |
| "길이가 k인 연속 구간" 중 최대/최소 | 고정 길이 윈도우 |
| "합이 S 이상인 가장 짧은 / 합이 S 이하인 가장 긴 연속 구간" + **양수** | 가변 길이 윈도우 |
| 정렬된 두 배열을 합치기, 공통 원소 찾기 | 배열마다 포인터 하나씩 |
| N이 10만 이상인데 O(N²) 풀이만 떠오른다 | 포인터가 되돌아갈 필요가 있는지 따져 본다 |

## 작은 입력으로 따라가기

**양 끝**: `a = [1, 3, 4, 6, 8, 11]`, 합 10

| left | right | 합 | 이동 |
|---|---|---|---|
| 1 | 11 | 12 | 크다 → right-- |
| 1 | 8 | 9 | 작다 → left++ |
| 3 | 8 | 11 | 크다 → right-- |
| 3 | 6 | 9 | 작다 → left++ |
| 4 | 6 | 10 | 찾음 |

15개 쌍 중 5개만 확인했다.

**가변 길이**: `a = [2, 3, 1, 2, 4]`, 합이 7 이상인 가장 짧은 구간

| right | sum | while (sum ≥ 7) | best |
|---|---|---|---|
| 0 | 2 | - | - |
| 1 | 5 | - | - |
| 2 | 6 | - | - |
| 3 | 8 | 길이 4 기록, left=1, sum=6 | 4 |
| 4 | 10 | 길이 4, left=2, sum=7 → 길이 3 기록, left=3, sum=6 | 3 |

## 복잡도

- 시간 O(N): 반복문이 중첩되어 보여도, `left`와 `right`가 **각각 최대 N번**만 움직이므로 전체 이동 횟수는 2N 이하다.
  ("안쪽 while이 있으니 O(N²)"이 아니다. 안쪽 while의 **총** 실행 횟수를 센다.)
- 정렬이 필요하면 O(N log N).
- 공간 O(1) 추가.

## 자주 하는 실수와 반례

| 실수 | 반례 / 증상 |
|---|---|
| **음수가 있는 배열에 가변 길이 윈도우** | `[4, 5, -8, 1]`, 합 ≤ 2인 가장 긴 구간: 정답 4(전체), 윈도우 방식은 2. 음수가 있으면 [05단원](../05-prefix-sum/README.md)의 누적합+해시 등을 검토 |
| 정렬되지 않은 배열에 양 끝 투 포인터 | 근거가 성립하지 않음 |
| `while (left <= right)` | 같은 원소를 두 번 사용 |
| 안쪽을 `if`로 써서 `left`를 한 번만 이동 | `[1, 1, 1, 10]`, S=10 → 길이 1을 놓침 |
| 고정 길이에서 나가는 원소 인덱스 오류 | `a[right - k]`가 아니라 `a[right - k + 1]`을 뺌 |
| 합을 `int`로 | 10^9짜리 원소 여러 개 |
| 답이 없는 경우 처리 누락 | 조건을 만족하는 구간이 없을 때의 출력 |
